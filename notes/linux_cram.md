# Linux — шпаргалка для співбесіди (нуль базових знань)

**Процес** — запущена програма, своя ізольована пам'ть.
**Потік** — виконання всередині процесу, ділить пам'ять з іншими потоками того ж процесу.

**fork()** — процес клонує сам себе, з'являється друга, майже ідентична копія (дитина).
**exec()** — процес замінює свій код на код іншої програми (той самий процес, новий вміст).
Разом: `fork()` потім `exec()` = "запустити нову програму з поточної" (так робить shell).

**Zombie-процес** — дитина завершилась, а батько ще не "забрав" її код завершення. Висить у таблиці процесів, поки батько не спитає.
**Orphan-процес** — батько помер раніше за дитину; дитину бере під опіку системний процес init (PID 1).

**Сигнал** — сповіщення процесу ззовні ("зроби щось" / "зупинись").
- `SIGTERM` — "будь ласка, завершись" — процес може перехопити й акуратно прибратись.
- `SIGKILL` — "вбити негайно" — перехопити/заблокувати НЕМОЖЛИВО, ОС просто вбиває.
- `SIGINT` — те, що шле Ctrl+C.

**Статична бібліотека (.a)** — код вшивається прямо в програму при збірці. Бінарник більший, ні від чого зовнішнього не залежить.
**Динамічна бібліотека (.so)** — код підвантажується під час запуску з окремого файлу. Бінарник менший, але той `.so` мусить бути в системі.

**File descriptor** — число, яким процес позначає відкритий файл/сокет. `0` = stdin, `1` = stdout, `2` = stderr.

**IPC (як процеси обмінюються даними)**
- **pipe** — односторонній канал, зазвичай між батьком і дитиною.
- **shared memory** — шматок пам'яті, доступний двом процесам одразу — найшвидше, бо без копіювання.
- **socket** — може бути і локальним (Unix socket), і мережевим (TCP/UDP).

**mmap** — "показати" файл так, ніби це шматок звичайної пам'яті — читаєш/пишеш напряму, без окремих команд читання/запису файлу.

**Інструменти для дебагу:**
- `gdb` — дебагер: ставиш точку зупинки, дивишся змінні, дивишся стек викликів (`bt`).
- `strace` — показує, які системні виклики робить програма (які файли відкриває, що читає/пише).
- `valgrind` — шукає memory leaks і некоректну роботу з пам'яттю, запускаючи програму "під лупою".
- **core dump** — знімок пам'яті процесу в момент краху; відкривається в `gdb`, щоб побачити, де саме все впало.

**Права доступу до файлу** — три групи: власник / група / всі інші, кожній можна дати read(4)/write(2)/execute(1). `chmod 755` = власнику все (7=4+2+1), решті — тільки читати й виконувати (5=4+1).

**Hard link vs symlink** — обидва "ще одне ім'я для файлу".
- **Hard link** — вказує прямо на дані файлу; видалиш оригінал — дані живі, доки є хоч один лінк.
- **Symlink** — вказує на **шлях** до файлу; видалиш оригінал — symlink лишається, але "висить у порожнечу" (broken link).

**systemd / служба (service)** — спосіб запустити програму у фоні на Linux-сервері, з автозапуском при завантаженні системи й автоматичним перезапуском, якщо впала.

**Realtime-пріоритет потоку** (актуально для дронів/телеметрії) — звичайні потоки по черзі ділять CPU; `SCHED_FIFO`/`SCHED_RR` дає потоку пріоритет "не чекай черги" — важливо для коду, що керує польотом і не може запізнюватись.
